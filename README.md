# MakeMeSmall

**https://makemesmall.vercel.app**

Пакетное сжатие картинок в браузере. Кидаешь папку — получаешь ZIP со сжатыми файлами.
Ничего не загружается на сервер: всё считается локально в Web Workers.

## Деплой

Проект подключён к Vercel (`hellowrld/makemesmall`), production-ветка —
`claude/image-compressor-p00xqc`. Каждый push в неё пересобирается и выкатывается
автоматически. Сборка занимает ~3 с, на выходе статика без бэкенда.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # статика в dist/ — кладётся на любой хостинг
```

`dist/` — обычные статические файлы, бэкенд не нужен.

## Как это работает

**Качество подбирается для каждой картинки отдельно.** Вместо фиксированного `quality = 0.8`
воркер делает бинарный поиск по SSIM: жмёт превью 480 px на 5 итерациях, сравнивает с
оригиналом и берёт минимальное качество, при котором SSIM ещё выше порога. Гладкое небо
уедет на q ≈ 0.5, шумная текстура останется на q ≈ 0.95. Поиск идёт на превью — поэтому
он почти ничего не стоит по времени.

Пороги SSIM: `Максимум` 0.9985, `Оптимально` 0.995, `Компактно` 0.985.

Остальное:

- **Параллельность** — пул воркеров по числу ядер (2–8), декод и энкод через
  `createImageBitmap` + `OffscreenCanvas`, главный поток не блокируется.
- **ZIP** — свой store-only писатель (`src/zip.ts`, ~90 строк). Сжатые картинки повторно
  не жмутся, поэтому deflate не нужен и сборка архива идёт со скоростью memcpy.
- **Защита от раздувания** — если результат оказался больше исходника, в архив уходит
  оригинал (строка помечается «уже оптимально»). Исключение: явный выбор PNG/JPEG —
  там конверсия и есть цель, и рост показывается честно как `+X%`.
- **EXIF-ориентация** учитывается, метаданные вырезаются (это часть экономии).

Измерено на 61 файле / 49 МБ: **4.9 с, −94%** (Chromium, 8 воркеров).

## Настройки

| Контрол | Значения | Смысл |
|---|---|---|
| Качество | Максимум / Оптимально / Компактно | порог SSIM |
| Формат | WebP / JPEG / PNG / Оригинал | контейнер на выходе |
| Разрешение | Оригинал / 4K / 2.5K / 1080p | ограничение длинной стороны |

Смена любого контрола пережимает уже загруженные файлы — оригиналы держатся в памяти.

## Ограничения

- **PNG на выходе — lossless.** Canvas не умеет квантовать палитру, поэтому PNG→PNG
  почти всегда возвращает оригинал, а JPEG→PNG раздувает файл в разы. Для скриншотов и
  графики берите WebP: он делает и lossless-подобное качество, и реальное сжатие.
- **Кодек — браузерный.** mozjpeg/oxipng через WASM дали бы ещё 5–10 %, но это +2 МБ
  бандла и втрое медленнее. Осознанный размен в пользу скорости.
- **HEIC** не декодируется вне Safari — такие файлы помечаются ошибкой.
- **ZIP без ZIP64**: архив больше 4 ГБ не соберётся (выдаст ошибку, а не битый файл).
- **AVIF** не добавлен: кодирование в браузере занимает секунды на картинку.

## Структура

```
src/main.ts    UI, drag&drop с обходом папок, состояние, сборка архива
src/worker.ts  декод, поиск качества по SSIM, энкод, CRC32
src/pool.ts    пул воркеров с очередью
src/zip.ts     store-only ZIP + CRC32
src/style.css  стили, светлая и тёмная тема
```
